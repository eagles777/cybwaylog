The problemTwo halves of database assurance

Most database security tooling answers “is this database configured correctly?” — a static question. It cannot answer the one that matters during an incident: “is something happening right now that shouldn't be?” Commercial SIEM and UEBA platforms do answer it, but they are closed boxes: you cannot see how their AI decides, and they publish no accuracy figures you can check.

Cybwaydb audits configuration (static state). Cybwaylog audits activity (dynamic behavior). Together they cover both halves — and both publish their governance architecture and their measured AI accuracy, so the claims are checkable rather than asserted.

ArchitectureGovernance, not just a model call

The LLM's role is deliberately bounded: it drafts, it never decides and never acts.

STAGE 1

Triage Agent

Reads the detected events and drafts an incident report — narrative, affected accounts, and a recommended response — as strict JSON.

STAGE 2

Independent Checker

Re-derives the truth from the raw audit rows and adjudicates PASS / REVIEW / QUARANTINE. Hallucinated accounts and injected instructions are quarantined. It never grades its own generation.

STAGE 3

Human Triage Gate

A person confirms, dismisses as a false positive, escalates, or files an expiring exception (NIST CA-5 style). Nothing closes without a logged human decision.

✓

Tamper-evident audit log

Every decision is chained to the SHA-256 of the previous entry; any edit, deletion, or reordering is detected. A SHA-256 manifest covers the run's outputs.

⚠

Red-teamed against itself

18 OWASP LLM Top 10-mapped injection, jailbreak, and exfiltration patterns — plus an injection canary planted in the log data itself. All quarantined.

There is no execute path anywhere in the codebase. Recommended responses are advisory; the dry-run always reports executed=False.

Try itQuick start

# everything below runs offline, with no API key and no cost
pip install -e ".[dev]"
pytest                                   # 150 tests, all offline, $0

cybwaylog init-log --out mylog.sqlite    # a synthetic trail you can edit
cybwaylog scan --db mylog.sqlite --out runs/latest
cybwaylog scan --clean --out runs/quiet  # quiet fortnight → zero detections

cybwaylog report --run-dir runs/latest --out report.html
cybwaylog verify --run-dir runs/latest   # check hash chain + manifest
cybwaylog benchmark --runs 50 --seed 42  # accuracy + ranking + alert fatigue
cybwaylog redteam                        # prove the injection canary is caught

SafetyScope and guarantees

  • Defensive only. No offensive or exploit code. “Red-team” here means self-testing this tool against published OWASP LLM Top 10 patterns.
  • Synthetic data only. Every user, host, address, and event was generated for testing. No real database, log, credential, or organizational data exists in the repository.
  • No execute path. Recommended responses are advisory, and nothing resolves without a logged human decision.
  • Zero-spend by policy. The budget ceiling defaults to $0.00 and is checked before any call. A live run would require a free-tier key with no billing attached; an exhausted quota stops the run rather than falling back to anything paid.
  • Data minimization. Only event metadata would ever reach a model — never free-text fields, never credentials.
